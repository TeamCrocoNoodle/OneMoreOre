# 대량 타격 시 원석 회전 폭주 수정 — 2026-09-15

원석 흔들림의 회전 속도가 타격마다 제한 없이 더해졌다. 연속 타격으로 `hit_stop`이 계속 갱신되는 동안에는 속도만 쌓이고 흔들림은 멈췄다. 이후 긴 프레임에서 기존 Euler 적분이 큰 속도를 증폭해 원석이 과도하게 회전했다.

실제 표면 9개에 피해를 총 4,096번 적용한 뒤 250ms 프레임을 실행해 재현했다. 수정 전 내부 회전 속도는 약 3,264rad/s, 흔들림 벡터의 길이는 각도로 약 128,564도까지 커졌다. 이는 내부 누적 수치이며 화면에서 그 횟수만큼 회전했다는 뜻은 아니다.

## 수정

- 동시 타격은 하나의 흔들림 속도에 합산하되 최대 2.4rad/s로 제한한다. 피해와 보상 처리는 각 타격대로 실행한다.
- 기존 강성 170, 감쇠 15의 스프링을 해석적으로 계산한다. 반복 보정 루프나 추가 Tween 없이 프레임 간격에 안정적인 한 단계 계산을 사용한다.
- 타격 정지 중에도 스프링은 감쇠한다. 효과가 멈춘 동안 에너지를 저장했다가 한꺼번에 풀지 않는다.
- 흔들림은 총 6도 이내로 제한하고 상한 밖으로 향하는 속도를 제거한다. 충분히 가라앉으면 정확히 영점으로 정리한다.
- 약 0.03도 미만의 미세한 변화는 장면 좌표에 재적용하지 않는다. 수천 자식 노드의 불필요한 좌표 갱신을 줄인다.
- 플레이어가 회전시킨 `shell`과 효과용 `rock_motion`을 계속 분리한다. 새 원석과 보스의 기존 흔들림 초기화도 유지한다.

동일한 4,096회 재현 시험은 수정 후 속도 2.4rad/s, 250ms 뒤 약 0.905도로 끝났다. 피해량은 정확히 4,096이 적용됐다. 지속 타격과 4초까지의 프레임 간격 시험에서도 최대 6도를 지켰다.

## 실제 렌더링과 Lag 확인

Windows / Godot 4.7.2 Compatibility / RTX 4060 Laptop / 1280×900, VSync 해제 및 최대 120fps 조건이다. 최대 원석 4,736조각·보석 68개·전체 강화를 사용했다. [측정 원본](rock_wobble_performance.json).

기존 성능 검사에서 중지해 두었던 원석 흔들림 갱신을 이번 검사에 포함했다. 피해·파편·공명·물리 좌표 갱신·렌더링·후속 자원 정리를 실행한다. 일반 입력과 자동 도구 AI는 정지해 작업량을 통제한다. PNG 읽기와 저장 구간은 프레임 측정에서 제외한다. 과거처럼 흔들림을 중지한 기록과 동일 조건의 A/B 결과로 취급하지 않는다.

| 구간 | 프레임 수 | 중앙값 | p95 | 최대 |
| --- | ---: | ---: | ---: | ---: |
| 최대 원석 정지 화면 | 60 | 8.26ms | 8.56ms | 15.59ms |
| 4,736개 동시 파괴와 후속 처리 | 195 | 8.29ms | 10.27ms | 34.82ms |
| 매 프레임 9조각 파괴와 강제 공명 | 30 | 35.05ms | 39.48ms | 47.95ms |
| 이후 공명 연쇄 | 99 | 32.11ms | 40.06ms | 43.10ms |
| 남은 4,423조각 분쇄와 후속 처리 | 189 | 8.31ms | 8.56ms | 18.30ms |

전체 파괴 호출은 4.15ms, 분산된 보상 처리가 완료되기까지는 153.32ms였다. 준비된 최대 원석 전환은 이후 두 프레임을 포함해 41.27ms, 부분 준비된 원석 완성은 650.54ms였다. 사전 준비 없는 생성은 2.75초, 그 구간의 최대 프레임은 94.15ms였다.

**회전 폭주는 해결됐지만 극한 연속 파괴·공명에는 렉이 남는다.** 해당 스트레스 구간의 중앙값은 약 29fps, 가장 긴 프레임은 약 21fps에 해당한다. 일반 플레이 전체의 평균 FPS나 다른 기기의 성능을 뜻하지 않는다. 전체 파괴 구간에는 작업 완료 뒤 효과·정리 180프레임도 포함된다.

실제 GPU 시험의 흔들림 최대값은 부동소수점 오차를 포함해 6.000001도였고, 오류·보상 누락·유출 RID 보고 없이 종료했다. 계산과 좌표 적용을 합한 비용은 전체 1,748개 표본에서 중앙값 0.003ms, p95 2.93ms였다. 이 표본은 정지·준비·파괴 구간을 모두 포함하므로 순수 수학 계산 비용으로 해석하지 않는다.

## 회귀 검증

흔들림 506개, 채굴 1,006개, 주 도구 225개, 범위 표시 514개, 정산 114개, 극한 채굴 1,267개, 보스 395개 검사 모두 통과했다. 15~240fps에서 같은 시간의 단일 타격 궤적, 지속 타격 후 영점 복귀, 플레이어 회전 보존과 새 원석 초기화를 포함한다.

정산 검사에는 이번 수정 전 코드에서도 동일한 실패 4개가 있었다. 수동으로 정지시킨 테스트가 기존 비동기 원석 준비를 끝내지 않은 것이 원인이었다. 테스트에서 준비를 명시적으로 완료하고, 준비된 원석이 추가 등장 지연 없이 채굴 가능해지는 기존 동작을 확인하도록 고쳤다. 원석 생성이나 정산의 실제 동작은 변경하지 않았다.

```powershell
godot --headless --path . --script res://tests/validate_rock_wobble.gd
godot --path . --script res://tests/profile_rock_wobble.gd -- --tag=wobble_fix
```

GPU 시험 중 다른 성능 검사는 동시에 실행하지 않는다. 원본 JSON과 화면은 `artifacts/performance/extreme_wobble_fix*`에 저장된다. 기능 검사는 기존 `tests/run_performance_validation.ps1 -Suite Core`에도 포함했다.
