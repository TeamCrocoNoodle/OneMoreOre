## 처리 방식

- **대량 파괴를 분할 처리한다.** 256개를 넘는 대상은 프레임당 약 3ms CPU 예산의 작업으로 처리한다. 원석 전체가 파괴되는 경우 활성화 프레임에 원석을 숨긴다. 각 조각의 피해·등급별 보석·일반 돌·회복·Gold는 기존 규칙으로 정확히 한 번 반영한다. 이 짧은 처리 중에는 채굴 입력과 제한 시간을 잠시 멈춰 정산 직전 보상이 빠지는 일을 막는다. 작은 작업은 즉시 완료한다.
- **해제도 분할한다.** 이미 숨기고 충돌을 끈 노드를 프레임당 최대 48개, 약 1.2ms 예산으로 해제한다. 수천 노드를 `queue_free()`한 뒤 같은 프레임 끝에서 한꺼번에 해제하던 병목을 피한다. 상위 컨테이너는 모든 자식의 정리가 끝난 후 해제한다.
- **정교한 파편을 중요한 타격에 집중한다.** 한 렌더 프레임에 한 조각은 기존 균열에 맞춘 입체 파편을 만든다. 동시에 부서지는 나머지 조각은 기존 입체 돌가루 배치를 사용한다. 활성 충격 링은 최대 8개, 입체 파편은 최대 80개로 유지하며 원석 교체 때도 풀을 재사용한다.
- **주변 타격의 균열 생성 비용을 제한한다.** 직접 겨냥한 타격은 즉시 갱신한다. 주변 조각은 HP·타격 횟수·반짝임을 즉시 반영하고, 최근 타격 위치 최대 2개를 보관해 균열을 갱신한다. 갱신 대기는 최대 96개, 프레임당 최대 2개이며 직접 타격과 약 3.5ms 예산을 공유한다. 이후 겨냥하거나 노출되면 남은 갱신을 반영한다. 파괴된 조각의 마지막 보이지 않는 균열은 만들지 않는다.
- **공명 검색 범위를 줄인다.** 큰 원석은 공간 격자로 근처 조각만 찾아 실제 거리를 판정한다. 공격당 96회·대기열 256개·프레임당 3회의 기존 반응 한도를 채우면 불필요한 검색과 효과 요청도 멈춘다.
- **구멍 뒤로 보일 수 있는 조각만 그린다.** 처음에는 외층만 렌더링한다. 파괴 지점, 조각의 전체 모서리 범위, 안쪽 층 반지름을 사용해 가능한 시야 범위를 보수적으로 열어 준다. 숨긴 조각도 HP·충돌·범위 피해 판정은 유지한다. 정지 화면의 드로 호출은 기존 기록 5,233회에서 이번 기록 2,193회였다.
- **고정된 직교 카메라에 그림자 투영을 맞춘다.** 방향광을 단일 직교 그림자로 바꿔 같은 원석을 여러 그림자 구간에 반복 제출하는 비용을 줄였다. 그림자 자체는 유지한다. [Godot DirectionalLight3D 문서](https://docs.godotengine.org/en/stable/classes/class_directionallight3d.html).

## 원석 준비와 캐시

기존 절차적 모델에서 단계별 4종, 총 28개 원석 형태를 압축 리소스로 만들었다. CPU 정점·충돌 점·소켓·파편 원본 데이터만 저장하며, GPU 메시와 물리 형태는 프레임 예산 안에서 조금씩 생성한 뒤 재사용한다. 압축 리소스 총 크기는 약 154MiB다. 보석 위치·등급·특수 돌·체력·색상은 현재 진행도와 새 난수로 정하므로 캐시에 플레이어의 보상이 고정되지 않는다.

준비 과정은 다음과 같다.

1. 리소스를 비동기로 읽고 완료 상태를 확인한 뒤 가져온다. 로딩 완료 전에 동기적으로 기다리지 않는다. [Godot 백그라운드 로딩 문서](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html).
2. 현재 원석을 캐는 동안 다음 원석 하나를 프레임당 약 1.5ms CPU 예산으로 준비한다. 보스 전투 중에는 승리 후 원석을 준비한다. 모든 보석을 실제 조각 안에 넣고 특수 돌 설정도 끝낸다.
3. 준비된 장면은 보이지 않으며 현재 타격 광선에서 제외되는 별도 충돌 층을 사용한다. 현재 원석을 회전해도 다음 원석은 최종 등장 자세를 유지한다.
4. 교체 시에는 준비된 상위 노드의 표시와 유효 충돌 층을 전환한다. 수천 자식을 다시 붙이거나 위치를 다시 맞추지 않는다.
5. 준비 전에 너무 빨리 교체하면 현재 준비 작업을 약 5ms CPU 예산으로 이어서 끝낸다. 강화 구매로 수치가 달라진 경우에는 새 수치로 준비를 갱신한다.

리소스 형식·원석 형태 설정이 달라지면 저장된 형태를 거부하고 기존 절차적 생성으로 돌아간다. 단계가 바뀌면 다른 단계의 캐시를 비운다. 보석도 기존 12종 형태를 공유하되 각 보석의 재질·변환·충돌 객체는 독립적으로 유지한다. 최종 스트레스 작업 정리 뒤 장면 노드는 692개, Godot 정적 메모리는 약 486MiB였다. 이 메모리 지표에는 GPU 메모리나 전체 프로세스 사용량이 포함되지 않는다.

## 기능 검증과 재현

극한 상태 검증은 1,263개 검사, 0개 실패였다. 앞·옆·뒤 10방향과 깊은 채굴 구멍에서 **1,154개의 실제 물리 광선**을 비교해 숨긴 조각·준비 중인 원석·제거된 원석이 첫 타격 대상으로 잡히지 않는지 확인했다. 등급별 보석 68개와 일반 돌 4,668개의 정확한 지급, 부분 피해 보존, 처리 중 초기화, 수명 종료 후 해제, 지연 균열의 반짝임 소멸도 검사했다.
