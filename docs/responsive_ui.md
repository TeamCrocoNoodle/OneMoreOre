# 해상도 대응 UI

HUD, 정산·경매, 스킬 트리, 도구 상점은 `scripts/responsive_ui.gd`의 공통 배율을 사용한다. 프로젝트의 `canvas_items / expand` 변환을 반영하므로 화면 좌표, 보석 도착 위치, 버튼 클릭 영역이 함께 이동한다.

- 가로 화면 기준은 1200 × 850이다. 큰 화면의 배율 상한을 없앴다. 작은 창에서는 최소 배치를 확보하면서 글자 축소를 제한한다.
- 세로 화면은 420 × 740을 기준으로 배치한다. 고해상도 세로 화면도 세로 배치를 유지한다.
- 선반은 넓은 화면·중간 폭·좁은 화면의 고정 비율 모델을 사용하고, 전체를 동일한 배율로 맞춘다. 읽기 어려울 만큼 줄이는 대신 넘치는 선반은 스크롤한다.
- 가격표와 클릭 영역은 같은 3D 카메라에서 투영한다. 해상도만 바뀌면 렌더 텍스처를 조정하고 선반·도구 메시를 재생성하지 않는다. 선반 텍스처 최대 변은 2560, 확대 도구는 1536픽셀이다.
- 도구·스킬 설명은 높이가 제한된 스크롤 영역을 사용한다. 정산의 업그레이드·재채굴·경매 버튼은 한 행에서 공간을 나누며, 작은 화면에서는 재채굴 문구를 줄인다.

## 검증

`tests/validate_responsive_ui.gd`는 실제 게임 UI에 14가지 창 크기를 적용한다: 320×568, 360×800, 600×400, 640×360, 640×480, 800×450, 1152×800, 1280×720, 1920×1080, 2560×1440, 3840×2160, 3440×1440, 768×1024, 1080×2400.

검사 범위: 10행 정산과 3개 버튼, 일곱 보석 도착점, 도구 13종의 가격표·클릭 영역, 가로·세로 전환, 열린 구매 창의 리사이즈, 콘텐츠 배율 변경, 모델 캐시 유지, 긴 스킬 설명의 휠·터치·컨트롤러 스크롤, 보조 도구 버튼.

```text
godot --headless --path . --log-file .godot/responsive_validation.log --script res://tests/validate_responsive_ui.gd
godot --path . --log-file .godot/responsive_capture.log --script res://tests/capture_responsive_ui.gd
```

두 번째 명령은 실제 GPU로 4K, 작은 가로 화면, 일반·고해상도 세로 화면을 촬영한다. 결과는 `artifacts/responsive_*.png`와 `artifacts/responsive_ui_captures.json`에 저장된다. 검증용 자금과 해금은 테스트 인스턴스에만 적용된다.
